1 - O que são operações de "Commit", "Push" e "Pop" efetuadas num repositório?

  • Commit: Regista as alterações no repositório local, criando um ponto de referência no histórico do projeto que permite acompanhar o que foi alterado.
  • Push: Envia os commits do repositório local para o repositório remoto, permitindo partilhar as alterações com a equipa e sincronizar o trabalho.
  • Pop: Recupera as alterações guardadas temporariamente no stash e volta a aplicá-las no diretório de trabalho. Ao contrário do apply, o pop remove as alterações do stash após as aplicar.

2 – Quais são as vantagens de usar Branches num repositório git?

Usar branches num repositório Git permite desenvolver novas funcionalidades e corrigir erros sem afetar diretamente o código principal do projeto.

As principais vantagens são:

  1. Isolamento: Permite desenvolver funcionalidades ou corrigir erros sem alterar diretamente o código principal do projeto.
  2. Trabalho em Paralelo: Facilita o trabalho paralelo no projeto, permitindo que cada pessoa desenvolva as suas alterações de forma independente.
  3. Organização e Revisão: Permite separar as alterações por funcionalidades ou tarefas, facilitando a revisão do código antes de integrar as alterações no código principal do projeto.

3 – Nos Merges de conteúdos resultantes de um "Pop" podem resultar em conflitos. Em que consistem e como podem ser resolvidos esses conflitos?

Um conflito de "Pop", ocorre quando o código recuperado e o código atual mexem exatamente nas mesmas linhas e no mesmo ficheiro. O Git bloqueia o processo porque não tem capacidade de adivinhar qual é a versão correta.

Para resolver, tipicamente seguimos estes passos:

  1. Editar: Procurar nos ficheiros afetados as marcações de conflito inseridas pelo Git (<<<<<<<, =======, >>>>>>>) e ajustar o código para a versão correta, apagando esses símbolos no final.
  2. Confirmar: Executar o comando git add <ficheiro>, para indicar ao Git que o conflito daquele ficheiro está resolvido.
  3. Limpar: Executar o comando git stash drop, pois quando há conflitos, o Git não apaga o stash automaticamente por precaução.

4 – "Clone" e "Fork" são formas diferentes de replicar um repositório Git. Quais as diferenças entre eles?

  • Fork: Permite criar uma cópia de um repositório na nossa própria conta, seja no GitHub ou noutra plataforma que suporte esta funcionalidade.
  • Clone: Permite copiar um repositório para o nosso computador, para podermos aceder aos ficheiros, fazer alterações e trabalhar no projeto localmente.
